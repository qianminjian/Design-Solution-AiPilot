## 〇、远程验证环境执行说明（2026-08-01 更新）

### 0.1 执行策略

**所有 SIT 验证类任务统一在远程服务器实施，不在本地起容器。**

- 远程环境：7 个服务（postgres、minio、chromadb、core、ai、bff、web）+ Nginx 反向代理
- 远程资源充足，不限制内存，可并行 3-5 个子 agent
- 本地仅用于：代码编辑、单元测试（无外部依赖）、lint、typecheck、git 操作
- 详细规则见 `.trae/rules/remote-verification.md`

### 0.2 任务执行位置标注

下表中所有任务的"备注"列若标注 **[远程]** 表示在远程服务器执行，若标注 **[本地]** 表示可在本地执行。

| 任务类型               | 执行位置 | 说明                                |
| ---------------------- | -------- | ----------------------------------- |
| 单元测试（无外部依赖） | 本地     | `pnpm test` / `mvn test` / `pytest` |
| 集成测试               | 远程     | 需要真实 DB/对象存储/MQ             |
| E2E 测试               | 远程     | Playwright 脚本在远程环境执行       |
| 性能测试               | 远程     | k6 / JMeter 在远程执行              |
| 安全测试               | 远程     | OWASP ZAP / Nuclei                  |
| Chaos 测试             | 远程     | Chaos Mesh / Toxiproxy              |
| UAT/Pilot              | 远程     | 真实用户场景验证                    |

### 0.3 任务完成确认流程

1. **本地实现**：代码编辑 → 单元测试通过 → lint/typecheck 通过 → git commit & push
2. **远程验证**：SSH 登录 → git pull → docker compose up -d --build → 健康检查通过
3. **执行测试**：在远程环境执行对应任务测试套件 → 收集日志与报告
4. **结果确认**：本地分析测试报告 → 验证通过 → 在"状态"列勾选 `[x]` → 填写"完成日期"
5. **资源释放**：测试完成后可执行 `docker compose stop` 释放远程资源

## 九、使用说明

1. **任务完成**：在 `[ ]` 中改为 `[x]` 标记完成，并在"完成日期"列填入实际完成日期
2. **任务延期**：在"备注"列注明延期原因和新的预期完成日期
3. **任务变更**：在"八、变更记录"中记录任务新增、删除、优先级调整等变更
4. **门禁验证**：在"七、V0 退出门禁对照表"中记录门禁验证结果
5. **责任人指派**：在"责任人"列指派任务责任人
6. **计划日期**：在"计划完成日期"列填入预期完成日期，格式 YYYY-MM-DD
